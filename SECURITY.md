# Local IPTV security scope

The packaged desktop app runs a bundled interface inside sandboxed Electron with context isolation and no renderer Node.js access. It starts a Node HTTP service bound only to `127.0.0.1` on an ephemeral port. The preload bridge exposes only Exit. Navigation, new windows, and permission prompts are denied. Content policy allows bundled scripts and local media/proxy requests, with blob workers for video decoding.

Provider connections, playlists, and guide URLs live in the local service's memory. The renderer receives opaque, randomly generated media links instead of upstream URLs containing credentials. Control endpoints require a custom request header and validate loopback Host and same-origin requests. Media links are session capabilities, invalidated when the provider changes or disconnects. Remote provider content is never served as executable HTML. No telemetry or app-operated cloud service receives credentials. The provider and provider-specified CDN/guide servers necessarily receive their requests. HTTP provider URLs have the transport privacy of HTTP; use HTTPS when offered.

Optional Remember uses Electron safeStorage only when an available OS keyring is selected. Linux `basic_text` and unknown backends are rejected. Encrypted files have owner-only permissions. Browser development has no persistent provider store. Disconnect & forget deletes the saved file and aborts active requests. This protects stored credentials from casual disclosure; other software running as the same OS user may still access the user's keyring or process memory.

Playlist imports are limited to 12 MB and 50,000 channels. XMLTV parsing is streaming with limits on total decompressed bytes, nesting, programme count, and retained listings. External XML entities are never loaded, and internal DTD subsets are rejected. Provider errors are sanitized. Playlists containing arbitrary custom VLC headers, non-HTTP URLs, or unsupported HLS variables are not executed.

The React/Vinext/Cloudflare browser entry is retained for local development. Those server/build dependencies are not bundled into the desktop runtime. A dependency audit on September 9, 2026 reports 11 advisories in that retained development stack (8 high, 2 moderate, 1 low). The desktop service uses Node built-ins and the bundled XML parser, independent of that framework stack. Keep the development entry bound to localhost and address the advisories before any public hosting. This app is not a remotely accessible IPTV relay.

Do not post passwords, credential-bearing IPTV/EPG URLs, OAuth tokens, or API keys in issues. Reproduce provider problems with a sanitized fixture whenever possible.
